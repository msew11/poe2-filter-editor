# 功能配置目录

本功能使用的静态 JSON 配置统一放在 `src/config/`，通过 `index.ts` 导出给界面使用。以后新增物品底材等配置时也放在这里。配置随应用一起构建，修改后需重新构建；开发模式自动更新。

## item-classes.json

来源为 [RePoE 的 PoE 2 数据](https://github.com/repoe-fork/poe2)，当前快照版本 `0.5.5.4.2`。文件内记录了固定提交、原始数据链接及核对日期，可追溯更新。

完整原表有 118 条记录：`classes` 收录 93 条有名称的记录，对应 90 个不同的过滤器匹配值；`unnamedClassIds` 保留其余 25 条空名称内部记录的 ID，不作为匹配选项。

| 字段 | 用途 |
| --- | --- |
| `id` | 游戏内部类别标识，用于关联数据，不用于 Class 精确匹配 |
| `value` | 英文完整类别名，原样写入过滤器 Class 条件 |
| `labelZh` | 界面中文说明译名，非官方本地化数据，不写入过滤器 |
| `category` / `categoryId` | 原始数据的分类信息，可能为空，不能替代匹配值 |
| `baseItemCount` | 同一数据快照中关联的底材记录数量，不代表发布状态或掉落数量 |

原表包含系统、历史遗留及可能尚未启用的类别。保留完整原表是为了数据完整性，不意味着所有类别目前都会掉落。不要仅根据 `baseItemCount` 或 `release_state` 推断是否已在游戏中启用。

创建规则中的类别选择显示中文及英文，按 `value` 去重，选中后将英文值追加到匹配值列表；已存在的完整值不会重复追加。保留手动编辑，支持部分匹配及未来新增名称。

更新时，从同一个固定提交读取 `data/item_classes.json`、`data/base_items.json` 和 `exported-version.txt`，同步维护译名、统计及来源信息。保留英文单复数：例如 `Expedition Logbook` 与 `Expedition Logbooks` 是不同的匹配值。

## 词缀与底材

`crafting-data.json` 由 `npm run data:build-crafting` 从下述原始快照和 `item-affix-pools.json` 离线生成，仅在做装页面按需加载。收录已发布、`domain = item`、有普通词缀池的底材及相关词缀，排除珠宝、药剂、护符和地图类特殊规则物品，以及有 `conditionalMods` 的池。底材通过 `pool` 索引共享的 `modPools`，运行时展开为 `modIds`；词缀保留原始 ID、互斥组、生成/出现权重、附加标签、数值范围、名称与英文文本。中文导入别名在 `src/lib/crafting.ts` 中维护，中文显示名称、属性模板、组合伤害区间与单位换算在 `src/lib/crafting-localization.ts` 中维护。属性模板覆盖当前全部普通做装词缀；名称为界面说明译名，未收录的词缀名称采用属性说明，原英文名称留在悬停提示中。底材译名尚未完整覆盖。显示层不修改模拟中保存的原始 stat 数值，导入时按属性单位还原。

`poe2/base_items.json`、`poe2/mods.json`、`poe2/mods_by_base.json` 原样保存与类别表相同固定提交的原始数据，分别包含 5,496 条底材、16,784 条词缀，以及按底材标签组织的词缀池。原表保留普通、亵渎、精华、暗金等所有来源及生成条件，供后续功能查询；不会把这些大表打包到首屏 JavaScript。

`item-affix-pools.json` 是派生的 689 个底材标签词缀池，包含底材 ID、标签、普通前缀/后缀、亵渎前缀/后缀。词缀列表按 `type` 和 stat ID 组合分系列，保存词缀 ID 到需求物等的映射；词缀文字、数值范围及互斥组可用 ID 关联 `poe2/mods.json`。普通词缀采用上游 `mods_by_base` 的适用列表并限定底材 domain、排除精华专属；亵渎词缀按 `domain = desecrated`、前后缀类型和有序的生成权重匹配底材标签。权重匹配以第一条命中为准，0 权重也会终止匹配。

`item-affix-levels.json` 是供界面加载的轻量类别汇总，48 个类别具有适用词缀。每项保留 `ordinaryT1Level`（普通）、`desecratedT1Level`（亵渎）、`allT1Level`（两者合计），无适用词缀时为 `null`。不能用真假判断过滤等级 1。

这里的 T1 是按适用词缀池中每个系列最高 `required_level` 推导的最高档等级门槛，不能读取词缀 ID 末尾数字当作 Tier，也不能使用全表最高档代替具体底材池最高档。类别门槛取所有关联底材池的最大值，包含源表中的系统、历史和未启用记录，不能作为当前掉落状态的判断。特殊工艺与 `conditional_mods` 原样保留，不计入普通门槛；同等级多档的强弱、机制额外限制仍需按游戏规则核对。此门槛表示各词缀最高档的等级条件，不代表它们能同时出现。

```sh
npm run data:import-affixes  # 按 item-classes.json 中的固定提交下载三张表并重新生成
npm run data:build-affixes   # 离线使用已保存的三张表重新生成
```

类别选择器支持搜索中英文和连续勾选/取消，不会因选择一项而关闭；点击按钮、外部、移走焦点或按 Escape 收起。下拉列表通过 portal 放在当前规则弹窗内，使用绝对定位浮在内容之上，不占用字段高度、不改变弹窗或滚动内容的尺寸；随滚动和窗口尺寸调整位置，上下空间不足时翻转方向，列表内部滚动。

搜索框也支持按当前所选 T 阶对应的合计最低物等过滤：`71` 精确匹配，`>=71`、`<=82`、`>70`、`<83` 比较，`71-82` 区间（含端点）；可组合名称和等级，例如 `戒指 >=65`、`Rings >=65 <=71`，所有条件需同时满足。更换 T 阶后使用新档位的门槛重新过滤。无适用词缀的类别只参与名称搜索，不会按物等 0 匹配数值条件。

添加类别前可以选择 T1–T13，选项显示“全 Tn ≥ 物等”，鼠标悬停可查看普通和亵渎各自门槛。每个系列按需求物等降序排列取第 n 档，再跨系列和同类别底材池取最大值；不足 n 档的系列取最低档，表示所有词缀均能达到 Tn 或更高。单档亵渎词缀因此仍然可能决定整体门槛。同等级多档的物等相同，原始数据没有显式 Tier，档位按此前规则推导。`item-affix-levels.json` 的 `maxTier` 来自最大系列档数，`byTier[n - 1]` 保存普通、亵渎和合计门槛，无词缀类别为 `[]`。这里只追加类别值，不自动修改规则的 `ItemLevel` 条件；T 级选择仅用于当前字段的等级参考。


做装数据库通过 `npm run data:build-crafting` 离线生成，包含 1,825 个底材、1,412 条普通及特殊词缀。`modPools` 和 `specialPools` 共享相同底材的词缀列表，完整数据库约 3 MB，进入做装页面时才加载。生成器从原始表筛选 `domain = item` 的腐化词缀，避免引入怪物及遗物效果；亵渎继续使用已派生的适用池。

`poe2/essences.json` 保存精华到物品类别、保证词缀 ID 的映射，来源为 PathOfBuildingCommunity/PathOfBuilding-PoE2 的固定提交 `bb52d6b368307457eb9c54bb13f1829993d390b1`，源地址及游戏数据版权保存在文件内。仅采用能够与本地原始 mods 表关联的低阶、普通、高阶、完美精华。显示用的防御/属性占位词缀按当前底材普通池中的 stat 与数值范围解析为实际词缀，无法解析的组合不提供。腐化精华未导入。精华译名为界面译名；原文名称仍保存用于核对。
