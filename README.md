# Exile Forge · 流放之路 2 过滤器工坊

暗金风格的 React 页面工程：顶部 Header、左侧导航、多标签工作区，以及独立规则库和过滤器库。

## 启动与检查

这是一个由 `package.json` 管理的 React + TypeScript + Vite 前端工程。请在 `poe2-filter-editor` 目录中执行命令；该目录是工程根目录。

需要 Node.js 20.19+ 或 22.12+，推荐 Node.js 24 LTS。项目使用 pnpm 锁定依赖，已安装依赖后，npm 与 pnpm 都可以运行 `scripts`。

```sh
pnpm install
pnpm start
```

当前电脑已经安装依赖，可以直接使用 npm 启动：

```sh
npm start
```

| scripts | npm 命令 | 用途 |
| --- | --- | --- |
| start | `npm start` | 启动开发服务 |
| dev | `npm run dev` | 启动开发服务，与 start 相同 |
| typecheck | `npm run typecheck` | TypeScript 类型检查 |
| build | `npm run build` | 类型检查并生成 dist/ |
| preview | `npm run preview` | 预览已经生成的生产构建 |
| test | `npm test` | 运行规则逻辑测试 |

浏览器访问 http://127.0.0.1:5173 。也可以在编辑器的 NPM Scripts 面板选择 `start` 运行。当前电脑保留 `./start.ps1` 兼容入口，该脚本最终调用同一个 start 脚本。

## 规则库

- 规则页使用紧凑单行布局，支持创建、编辑、删除独立规则。
- 每条规则支持“复制”：打开已填入原规则内容的副本弹窗，自动生成副本名称，可修改后保存；新规则放在原规则之后，字段和规则 ID 独立，取消则不创建副本。
- 拖动规则左侧手柄可调整列表顺序，也支持键盘操作；顺序自动保存至本机，不代表执行优先级。
- 每条规则默认折叠规则文本，可点击右侧“文本”按钮展开或折叠。
- 创建与编辑共用弹窗，支持命名、Show/Hide 切换；编辑时载入原有字段。
- 字段使用紧凑行布局，字段名、选项与删除操作横向排列；复杂字段和窄屏自动换行，可通过手柄拖动或键盘调整顺序。
- 手柄获得焦点后，空格拾起、上下方向键移动、空格放下，Escape 取消。
- 支持 25 种字段：品质、稀有度、物品/区域/掉落等级、堆叠、孔数、途石阶级、未鉴定阶级、基础防御、类别、底材、鉴定/腐化/镜像/双重腐化、颜色、字号、音效、光柱、小地图图标。
- 同类型字段允许重复添加，例如 ItemLevel >= 70 与 ItemLevel <= 85。
- 物品类别支持从中英文类别表追加匹配值，保留手动输入；类别来自统一配置目录 `src/config/`，含系统及历史类别，详情见该目录说明。
- 类别下拉以浮层展开，不撑高规则弹窗；支持搜索、连续勾选，选中后保持展开。添加类别前可选择 T1–T13，有词缀的类别显示普通及亵渎词缀全部达到所选 T 级或更高的最低物等参考，同类底材取最高门槛，不足该档数的系列取最低档。悬停可查看普通与亵渎各自门槛；需要按此门槛过滤时，另加物品等级条件。
- 弹窗底部实时生成规则文本；保存前校验名称、数值范围和文本值。
- 空字段规则合法，会匹配所有物品，弹窗底部会提示。
- 取消关闭弹窗会丢弃草稿；保存编辑会更新原规则并保留 ID 和列表位置，自动保存至本机。

## 过滤器编辑

- 原“过滤器源码”页面改为过滤器库，支持创建、命名、编辑、删除多个过滤器。
- 创建与编辑沿用规则编辑的弹窗布局，“添加字段”对应为“添加规则”，从规则库选择规则及添加方式。
- 引用：按规则 ID 关联，原规则的名称、类型与字段修改会同步到所有引用它的过滤器。
- 拷贝：保存独立副本，可在过滤器中单独编辑；后续修改或删除原规则均不影响副本。
- 支持重复添加同一规则，拖动手柄或使用键盘调整执行顺序；从上到下执行，第一条命中的规则决定物品显示。
- 弹窗实时预览完整过滤器文本，保存前检查名称和至少一条规则。取消会丢弃草稿与副本编辑。
- 删除被引用的规则后，过滤器保留失效引用并提示修复，阻止复制与导出，避免悄悄遗漏规则。编辑过滤器，移除失效引用并添加其他规则即可修复。
- 列表可展开文本、复制或导出完整的 UTF-8 `.filter` 文件；以过滤器名称命名，按过滤器内部顺序组合规则。
- 过滤器、引用关系、副本与顺序自动保存到本机；兼容已有工作区和规则数据。删除过滤器不会删除规则库中的原规则。

## 其他页面

### 做装模拟

左侧“做装模拟”的工作台参考 Craft of Exile 的操作流程：顶部选择工艺和通货，左侧展示物品与空词缀位置，中间按前/后缀查看词缀系列与阶级，右侧查看历史、消耗和目标。通过“导入 / 更换底材”粘贴游戏中的繁体中文、简体中文或英文物品文本，核对底材与词缀后“开始模拟”；也可以选择普通底材与物等新建项目。上排选择通货类型，下排选择具体通货或阶级；选中后图标跟随鼠标，点击当前装备使用一次，右键或 Esc 取消。预兆集中显示在“已启用”栏，匹配通货使用后消耗。撤销位于做装记录，更换底材时自动带入当前装备文本。通货列表按当前宽度下各类型的最大高度预留空间，切换类型不推动装备区。悬停通货可查看游戏中文说明；精华按同类型归组，并从低阶到完美排序。工作台的简中 / 繁中 / English 按钮切换装备名、通货名、词缀与词缀名；其余操作界面保持中文。“复制物品”按当前语言生成完整物品文本，导入弹窗仅保留原文输入与底材、词缀确认。游戏中 Ctrl+C 复制物品；按住 Alt 可带出词缀名称、阶级与数值范围。

- 支持蜕变石、增幅石、富豪石、点金石、崇高石、混沌石、剥离石、神圣石、破裂石。使用当前固定数据快照的通货说明：点金石将普通或魔法物品重新生成为 4 词缀稀有物品；混沌石移除 1 条随机词缀再添加 1 条；破裂石要求至少 4 词缀的稀有物品，随机锁定 1 条词缀。
- 各工艺共支持 15 种征兆：富豪定向前/后缀，崇高定向前/后缀和双词缀，剥离定向前/后缀和双词缀，混沌定向移除前/后缀及最低需求物等移除，以及精华结晶和亵渎定向征兆。兼容征兆可组合，相反方向会被禁用。使用通货后消耗并清除所选征兆；操作失败不修改物品或记录。
- 按底材标签、生成权重、物等、词缀互斥组，以及魔法 1 前缀/1 后缀、稀有 3 前缀/3 后缀限制抽取；破裂词缀不被剥离、混沌或神圣操作修改。
- 词缀池默认显示完整普通词缀系列，可切换前后缀、搜索或只看可添加，展开系列查看各阶的物等与参考概率；不适用阶级显示物等不足、互斥等原因。点击靶心选择目标档位，同系列只能选择一个目标，达到该档或更高时标记命中；目标不改变随机结果。
- 历史按倒序列出通货、征兆、增减词缀，点击回看对应物品，回看时不能使用通货。“消耗”分别统计通货和征兆数量；支持撤销返还、重置、复制物品摘要。最多保存 200 步，进度与目标独立保存到本机，兼容上一版做装记录，切换标签和刷新后可继续。
- 提供底材搜索、选择和未知词缀手动确认。无法确认的属性会阻止模拟；不会丢弃未知词缀后继续生成。当前做装数据的全部属性均有中文说明，伤害区间按实际掷值显示，生命回复、偷取和暴击率转换为游戏单位。词缀名称使用中文说明译名，未收录名称时以属性名称说明，悬停可查看英文原名；底材中文名尚未完整覆盖。
- 新增高阶/完美蜕变、增幅、富豪、崇高与混沌石；按底材匹配低阶至完美精华，完美精华可搭配结晶征兆。亵渎支持占位、三选一揭示、持久化选项和定向征兆。腐化支持指定结果分支推演（无变化、附魔、重铸、额外插槽），完成后锁定物品；尚未复刻各分支随机概率。亵渎揭示及腐化附魔采用等概率参考模型，不能作为实测游戏概率。导入的传奇、腐化、镜像、未鉴定或未识别特殊词缀仍只保留文本。腐化精华、珠宝、药剂及额外专属征兆尚未支持。卡片中的词缀实时变化；“导入原文与属性”是快照，防御、装备需求和伤害等派生属性暂不重算。源码参考与许可证核对见 [docs/crafting-references.md](docs/crafting-references.md)。

做装数据库只在打开该页时加载，由固定快照离线生成；更新原始词缀数据后运行 `npm run data:build-crafting`。概率表示当前普通通货添加词缀时的相对权重，混沌石移除词缀后会重新计算词缀池；T 阶按当前底材同系列需求等级排序推导。

- 导航打开标签时去重，支持切换、关闭、键盘切换、空工作区。
- 工作区、规则库与过滤器库保存到浏览器 localStorage，支持旧版两条示例规则与独立规则库的数据迁移。
- 外观页提供试色参考，不会自动修改已创建规则；实际样式在规则中添加颜色/字号字段。
- 掉落预览只测试所选的单条规则，示例是区域/物品等级 80 的 Iron Cuirass。
- 过滤器编辑页查看、复制、导出由多条规则组合的完整过滤器。

## 设置与导出目录

- 点击右上角“设置”，在弹窗中选择“过滤器存放目录”，通过系统目录选择器选择游戏的过滤器文件夹。
- 目录设置立即保存到本机浏览器的 IndexedDB，刷新后恢复；浏览器仅提供文件夹名称，不能读取完整绝对路径。取消目录选择会保留原设置。
- 设置目录后，过滤器列表中的“导出”直接写入所选目录，同名文件会替换；重新打开浏览器后，首次导出可能需要再次授权。权限失效、目录被移动或写入失败时会显示错误。
- 点击“恢复默认下载位置”可清除目录设置，重新使用浏览器下载。
- 目录选择需要支持 File System Access API 的 Chrome / Edge，以及本机地址（localhost / 127.0.0.1）或 HTTPS。不支持的浏览器仍可使用默认下载方式。

尚未实现完整物品数据库、已有过滤器导入、账号及云端同步。预览是固定示例演示，未模拟实际游戏的音效、光柱和小地图效果。底材和类别值使用英文游戏名称，一行一个值。

## 技术与目录

React 19 + TypeScript + Vite + Tailwind CSS 4，UI 组件采用 shadcn/ui 的本地源码组织方式。Dialog/标签基于 Radix，字段排序使用 dnd-kit，保留 `components.json` 便于扩充。

```text
src/
  App.tsx                    # Header、导航、标签与持久化
  styles.css                 # 工坊主题与响应式布局
  config/                    # 功能静态 JSON 配置的统一目录
    item-classes.json        # PoE 2 完整类别快照、中文说明译名与来源
    index.ts                 # 配置导出与类别选项去重
    README.md                # 配置字段、覆盖范围与更新约定
  components/
    pages.tsx                # 规则库、外观与单规则预览
    filters-page.tsx         # 过滤器列表、增删改、文本与导出
    filter-builder.tsx       # 过滤器命名、规则引用/拷贝、排序及副本编辑
    rule-builder.tsx         # 创建/编辑弹窗、字段增删、拖动及实时文本
    fields/                  # 每个字段类型对应的编辑组件
      numeric-fields.tsx
      condition-fields.tsx
      action-fields.tsx
      index.ts               # 字段类型与组件的注册表
    ui/                      # 基础 UI 组件
  lib/
    rules.ts                 # 字段定义、校验、序列化和单规则匹配
    rules.test.ts            # 语法、匹配、校验与数据迁移测试
    filters.ts               # 过滤器模型、引用解析、序列化与持久化校验
    filters.test.ts          # 引用/拷贝、执行顺序、导出与迁移测试
    workspace.ts             # 工作区模型及兼容读取
    utils.ts
```

新增字段时，在 `lib/rules.ts` 定义默认参数与语法，添加对应编辑组件，并在 `components/fields/index.ts` 注册。规则文本使用稳定 ID 保存字段顺序，供过滤器组合与排序使用。

修改 `src/styles.css` 顶部变量可统一调整配色。没有依赖远程字体或游戏图片。

语法参考：[GGG 官方文档](https://www.pathofexile.com/item-filter/about)。
